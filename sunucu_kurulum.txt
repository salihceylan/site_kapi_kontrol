SUNUCU KURULUM NOTLARI (site_kapi_kontrol)
Tarih: 2026-03-02

PROJENIN AMACI
- Site/apartman yonetimi icin rol bazli (super_user, site_manager, apartment_owner) bir uyelik ve giris altyapisi sunmak.
- API'yi guvenli sekilde VPS uzerinde (Node.js + PostgreSQL + Nginx + SSL) canliya almak.
- Flutter istemcinin bu API uzerinden kayit, giris ve oturum yonetimi yapabilmesini saglamak.


Bu dokuman, projeyi sifirdan VPS uzerinde calisir hale getirmek icin basariyla uygulanan adimlari icerir.

1) VPS VE SSH HAZIRLIGI
- VPS'e baglanildi: ssh salihceylan@178.210.161.55 -p 22667
- SSH portu 22667 olarak kullanildi.
- SSH erisimi dogrulandi ve aktif dinleme kontrol edildi:
  sudo ss -ltnp | grep 22667

2) FIREWALL (UFW)
- Gerekli portlar acildi:
  sudo ufw allow 22667/tcp
  sudo ufw allow 80/tcp
  sudo ufw allow 443/tcp
- Durum kontrol edildi:
  sudo ufw status

3) DNS
- Subdomain dogru IP'ye yonlendirildi:
  api.gudeteknoloji.com.tr -> 178.210.161.55
- Dogrulama:
  dig +short api.gudeteknoloji.com.tr

4) PROJEYI SUNUCUYA ALMA
- Proje klasoru hazirlandi:
  sudo mkdir -p /var/www/site_kapi_kontrol
  sudo chown -R salihceylan:salihceylan /var/www/site_kapi_kontrol
- Repo klonlandi:
  cd /var/www/site_kapi_kontrol
  git clone https://github.com/salihceylan/site_kapi_kontrol .

5) NODE.JS VE PM2
- Node.js/NPM kuruldu.
- PM2 global kuruldu ve backend PM2 ile baslatildi:
  cd /var/www/site_kapi_kontrol/server
  npm install
  pm2 start npm --name kapi-api -- run start
  pm2 save
- PM2 surec kontrolu:
  pm2 list

6) POSTGRESQL (DOCKER)
- Docker + docker-compose kuruldu.
- PostgreSQL service ayağa kaldirildi:
  cd /var/www/site_kapi_kontrol
  docker-compose up -d postgres
  docker-compose ps
- Migration otomatik calisti, users tablosu olustu.
- Tablo kontrolu:
  docker exec -it site_kapi_kontrol_postgres psql -U postgres -d site_kapi_kontrol -c "\\dt"

7) BACKEND ENV AYARLARI
- server/.env olusturuldu ve duzenlendi:
  cd /var/www/site_kapi_kontrol/server
  cp .env.example .env
- .env icine en az su alanlar tanimlandi (TUM alanlar ve aciklamalari server/.env.example icindedir;
  sirlari bu belgeye/depoya YAZMAYIN):
  PORT=8080
  NODE_ENV=production
  JWT_SECRET=<en_az_32_karakter_rastgele_secret>   # bos/yer tutucu ise sunucu BASLAMAZ; 32 karakterden kisaysa yalniz uyari
  JWT_EXPIRES_IN=30d                                # bos birakilirsa varsayilan 30d
  DB_HOST=127.0.0.1
  DB_PORT=5432
  DB_NAME=site_kapi_kontrol
  DB_USER=<db_user>
  DB_PASSWORD=<db_password>
  SMTP_HOST / SMTP_PORT / SMTP_USER / SMTP_PASSWORD / SMTP_FROM   # dogrulama kodu, sifre sifirlama, yonetici daveti e-postalari
  PUBLIC_BASE_URL=https://api.gudeteknoloji.com.tr  # API'nin disaridan gorunen adresi (OTA/QR/davet baglantilari bundan uretilir)
  CORS_ORIGINS=<web istemci origin listesi>         # yalniz tarayici (web) istemcileri icin; mobil uygulama CORS kullanmaz
  COMPANY_API_KEY=<en_az_24_karakter_rastgele>      # company_qr_tool X-Company-Key basligi; tanimsizsa yalniz super_user JWT
  MQTT_HOST / MQTT_PORT / MQTT_USER / MQTT_PASSWORD  # API <-> broker (mqtts, TLS dogrulamasi acik)
  Istege bagli: DB_POOL_MAX (varsayilan 12), DB_STATEMENT_TIMEOUT_MS (30000), DB_CONNECT_TIMEOUT_MS (5000)
- Bagimliliklar (package.json degistiyse): cd server && npm ci --omit=dev
- PM2 env guncelleyerek restart:
  pm2 restart kapi-api --update-env
  pm2 logs kapi-api --lines 20 --nostream

8) HEALTH CHECK (LOKAL)
- API + DB baglantisi dogrulandi:
  curl http://127.0.0.1:8080/health
- Basarili sonuc:
  {"ok":true,"database":"connected"}

9) NGINX REVERSE PROXY
- Nginx kuruldu.
- site config dosyasi olusturuldu:
  /etc/nginx/sites-available/api.gudeteknoloji.com.tr
- proxy hedefi:
  http://127.0.0.1:8080
- config test + reload:
  sudo nginx -t
  sudo systemctl reload nginx
- HTTP test:
  curl -I http://api.gudeteknoloji.com.tr/health
  Sonuc: 200 OK

10) SSL (LET'S ENCRYPT)
- Certbot + nginx eklentisi kuruldu.
- Sertifika alindi ve https yonlendirmesi aktif edildi:
  sudo certbot --nginx -d api.gudeteknoloji.com.tr --redirect -m <mail> --agree-tos -n
- HTTPS test:
  curl -I https://api.gudeteknoloji.com.tr/health
  Sonuc: 200 OK

11) FLUTTER TARAFI
- Uygulama API URL ile calistirildi:
  flutter run --dart-define=API_BASE_URL=https://api.gudeteknoloji.com.tr
- Cihaz secim ekrani geldi ve uygulama acildi.

12) FINAL DOGRULAMA (YAPILACAK SON ADIM)
- Uygulama icinden kayit ve giris testini tamamla.
- Kayit/giris endpointlerinin canli calistigini teyit et:
  POST /auth/register
  POST /auth/login

Notlar:
- PM2 process adi: kapi-api
- API health endpoint: /health
- Uretimde DB portunu disariya acik birakmamak gerekir.
- SSH ayar degisikliklerinde oturum kapanmadan ikinci terminalden baglanti testi yapilmalidir.


GUVENLIK NOTLARI (yalnizca ek; yukaridaki adimlar degismedi)
- PostgreSQL: docker-compose.yml artik portu yalnizca 127.0.0.1:5432'e baglar ve POSTGRES_PASSWORD'u
  zorunlu tutar (depo kokundeki .env veya ortam degiskeni; varsayilan parola yoktur):
    cd /var/www/site_kapi_kontrol
    echo 'POSTGRES_PASSWORD=<guclu-parola>' >> .env && chmod 600 .env
    docker compose up -d postgres
  NOT: POSTGRES_PASSWORD yalnizca BOS veri dizininde uygulanir. Mevcut veritabanida parolayi
  ALTER USER ile degistirin ve server/.env DB_PASSWORD'u guncelleyin.
- Guvenlik duvari: 5432 (PostgreSQL) ve 8080 (Node) disariya ACIK olmamali; yalnizca 80/443 ve
  SSH portu aciktir. API 8080'de tum arayuzleri dinler; disaridan yalnizca nginx uzerinden erisilmeli
  (sudo ufw status).
- server/.env dosyasi: chmod 600, sahibi API kullanicisi; git'e girmez. JWT_SECRET en az 32 karakter
  rastgele olmali (bos/yer tutucu deger sunucuyu baslatmaz); COMPANY_API_KEY tanimlayin.
- Surec yonetimi: server/ecosystem.config.cjs (kapi-api). Ilk gecis:
    cd /var/www/site_kapi_kontrol/server
    pm2 delete kapi-api && pm2 start ecosystem.config.cjs && pm2 save
