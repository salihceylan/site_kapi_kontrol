MQTT KURULUM REHBERI (mqtt.gudeteknoloji.com.tr)

Amac
- API ve ESP32 cihazlarin TLS uzerinden ayni MQTT broker'a guvenli sekilde baglanmasi.
- Mobil uygulama MQTT'ye dogrudan baglanmaz; kapi komutu API'ye gider.
- Her ESP32 cihaz kendi MQTT kullanici/sifresiyle yalnizca kendi topic'lerine erisir.

Mimari
- Broker: Mosquitto (VPS)
- Domain: mqtt.gudeteknoloji.com.tr
- Port: 8883 (TLS)
- Auth: username/password
- Yetki: ACL (kullanici bazli topic izinleri)

Topic yapisi
- Komut: device/<UID>/cmd
- Durum: device/<UID>/state
- Olay: device/<UID>/event
- Erisilebilirlik: device/<UID>/availability

1) DNS hazirligi
- DNS panelinde asagidaki A kaydi olmalidir:
  mqtt.gudeteknoloji.com.tr -> 178.210.161.55
- Dogrulama:
  dig +short mqtt.gudeteknoloji.com.tr @8.8.8.8
  dig +short mqtt.gudeteknoloji.com.tr @1.1.1.1

2) Paket kurulumlari (VPS)
sudo apt update
sudo apt install -y mosquitto mosquitto-clients certbot python3-certbot-nginx

3) TLS sertifikasi (Let's Encrypt)
sudo certbot certonly --nginx -d mqtt.gudeteknoloji.com.tr -m MAIL_ADRESIN --agree-tos -n

4) Sertifika dosyalarini Mosquitto yoluna bagla
sudo mkdir -p /etc/mosquitto/certs
sudo ln -sf /etc/letsencrypt/live/mqtt.gudeteknoloji.com.tr/fullchain.pem /etc/mosquitto/certs/fullchain.pem
sudo ln -sf /etc/letsencrypt/live/mqtt.gudeteknoloji.com.tr/privkey.pem /etc/mosquitto/certs/privkey.pem

sudo chown -R mosquitto:mosquitto /etc/mosquitto/certs
sudo chmod 755 /etc/mosquitto /etc/mosquitto/certs
sudo chmod 644 /etc/mosquitto/certs/fullchain.pem
sudo chmod 640 /etc/mosquitto/certs/privkey.pem

5) MQTT kullanicilarini olustur
sudo mosquitto_passwd -c /etc/mosquitto/passwd api_bridge

# Her cihaz icin:
# UID ornek: D4C771A172E0
# Kullanici ornek: device_D4C771A172E0
sudo mosquitto_passwd /etc/mosquitto/passwd device_D4C771A172E0

6) ACL dosyasini olustur
sudo tee /etc/mosquitto/acl > /dev/null <<'EOF'
user api_bridge
topic read device/+/state
topic read device/+/event
topic read device/+/availability
topic write device/+/cmd

user device_D4C771A172E0
topic read device/D4C771A172E0/cmd
topic write device/D4C771A172E0/state
topic write device/D4C771A172E0/event
topic write device/D4C771A172E0/availability
EOF

Not:
- D4C771A172E0 ornek cihaz Unique ID'sidir.
- Sunucu cihaz kaydinda mqtt_username/mqtt_password olusturur. Broker tarafinda
  ayni kullanici/sifre mosquitto_passwd ve ACL dosyasina eklenmelidir.
- Ticari urun modunda cihaz kaydi sonrasi bu islem API tarafindan otomatik
  tetiklenir. Bunun icin 6.1 adimindaki sinirli sudo komutu kurulmalidir.
- Mobil uygulamaya MQTT kullanici/sifresi verilmez. Kapi acma komutu API'ye
  gider; API, api_bridge kullanicisi ile broker'a yazar.

6.1) Otomatik broker senkronu (ticari urun modu)
- API'ye sinirsiz sudo verilmez. Sadece asagidaki tek komutu sifresiz
  calistirma yetkisi verilir.

sudo install -o root -g root -m 0755 \
  /var/www/site_kapi_kontrol/server/scripts/kapi-mqtt-sync.sh \
  /usr/local/bin/kapi-mqtt-sync

sudo tee /etc/sudoers.d/kapi-mqtt-sync > /dev/null <<'EOF'
salihceylan ALL=(root) NOPASSWD: /usr/local/bin/kapi-mqtt-sync
EOF

sudo chmod 440 /etc/sudoers.d/kapi-mqtt-sync
sudo visudo -cf /etc/sudoers.d/kapi-mqtt-sync

- server/.env icinde otomatik senkron icin:
  MQTT_SYNC_COMMAND=sudo
  MQTT_SYNC_ARGS=-n /usr/local/bin/kapi-mqtt-sync
  MQTT_SYNC_TIMEOUT_MS=30000
  MQTT_SYNC_REQUIRED=true

- Elle test:
  cd /var/www/site_kapi_kontrol/server
  sudo -n /usr/local/bin/kapi-mqtt-sync

- Bu kurulumdan sonra yeni cihaz kaydedildiginde backend DB'de cihaz MQTT
  kimligini uretir, Mosquitto ACL/passwd dosyalarini senkronlar ve Mosquitto'yu
  reload/restart eder.
- server/.env icinde su degerler tanimli olmali:
  MQTT_HOST=mqtt.gudeteknoloji.com.tr
  MQTT_PORT=8883
  MQTT_USER=api_bridge
  MQTT_PASSWORD=<api_bridge_sifresi>
  MQTT_ALLOW_INSECURE_TLS=false

7) Mosquitto secure config (tek dosya tavsiyesi)
- Eski conf dosyalarini yedekle:
  sudo mkdir -p /etc/mosquitto/conf.d.bak
  sudo mv /etc/mosquitto/conf.d/*.conf /etc/mosquitto/conf.d.bak/ 2>/dev/null || true

- Yeni dosya:
sudo tee /etc/mosquitto/conf.d/10-secure.conf > /dev/null <<'EOF'
per_listener_settings true

listener 8883
protocol mqtt

allow_anonymous false
password_file /etc/mosquitto/passwd
acl_file /etc/mosquitto/acl

certfile /etc/mosquitto/certs/fullchain.pem
keyfile /etc/mosquitto/certs/privkey.pem
tls_version tlsv1.2
EOF

8) Ana config include kontrolu
- /etc/mosquitto/mosquitto.conf icinde su satir olmali:
  include_dir /etc/mosquitto/conf.d

9) Izinler ve servis
sudo chown mosquitto:mosquitto /etc/mosquitto/passwd /etc/mosquitto/acl
sudo chmod 640 /etc/mosquitto/passwd /etc/mosquitto/acl

sudo systemctl stop mosquitto
sudo pkill -9 mosquitto
sudo systemctl reset-failed mosquitto
sudo systemctl start mosquitto
sudo systemctl status mosquitto --no-pager
sudo ss -ltnp | grep 8883

10) Firewall
sudo ufw allow 8883/tcp
sudo ufw status

11) Test komutlari
- Subscriber (API bridge rolu, state okuma):
mosquitto_sub -h mqtt.gudeteknoloji.com.tr -p 8883 \
--cafile /etc/ssl/certs/ca-certificates.crt \
-u api_bridge -P 'SIFRE' \
-t 'device/D4C771A172E0/state' -d

- Publisher (ESP32 cihaz rolu, state yazma):
mosquitto_pub -h mqtt.gudeteknoloji.com.tr -p 8883 \
--cafile /etc/ssl/certs/ca-certificates.crt \
-u device_D4C771A172E0 -P 'SIFRE' \
-t 'device/D4C771A172E0/state' -m '{"locked":false}' -q 1 -d

- ESP32 cihaz kendi cmd topic'i disinda baska cihazin komutunu okuyamamali:
mosquitto_sub -V mqttv5 -h mqtt.gudeteknoloji.com.tr -p 8883 \
--cafile /etc/ssl/certs/ca-certificates.crt \
-u device_D4C771A172E0 -P 'SIFRE' \
-t 'device/BASKAUID/cmd' -d

12) ACL dogrulama (MQTT v5 ile net sonuc)
- api_bridge state'e yazmaya calisinca engellenmeli:
mosquitto_pub -V mqttv5 -h mqtt.gudeteknoloji.com.tr -p 8883 \
--cafile /etc/ssl/certs/ca-certificates.crt \
-u api_bridge -P 'SIFRE' \
-t 'device/D4C771A172E0/state' -m 'x' -q 1 -d

Beklenen: PUBACK RC:135 (Not authorized)

- api_bridge cmd'ye yazabilmeli:
mosquitto_pub -V mqttv5 -h mqtt.gudeteknoloji.com.tr -p 8883 \
--cafile /etc/ssl/certs/ca-certificates.crt \
-u api_bridge -P 'SIFRE' \
-t 'device/D4C771A172E0/cmd' -m '{"action":"pulse"}' -q 1 -d

Not: RC:16 gorulurse "No matching subscribers" demektir; yetki hatasi degildir.

13) Siklikla gorulen hatalar
- "Address already in use": Elle "mosquitto -c ... -v" calistirilmis ve port dolu.
  Cozum:
  sudo systemctl stop mosquitto
  sudo pkill -9 mosquitto
  sudo systemctl start mosquitto

- "Unable to open acl_file": acl dosyasi yok/izin hatali.
  Cozum:
  sudo chown mosquitto:mosquitto /etc/mosquitto/acl
  sudo chmod 640 /etc/mosquitto/acl

- Servis surekli fail:
  sudo journalctl -xeu mosquitto.service --no-pager | tail -n 80

14) Operasyon notu
- Servis ayakta oldugunda "sudo mosquitto -c /etc/mosquitto/mosquitto.conf -v" komutunu calistirma.
- Yonetim icin systemd kullan:
  sudo systemctl restart mosquitto
  sudo systemctl status mosquitto --no-pager
