MQTT KURULUM REHBERI (mqtt.gudeteknoloji.com.tr)

Amac
- API ve ESP32 cihazlarin TLS uzerinden ayni MQTT broker'a guvenli sekilde baglanmasi.
- Mobil uygulama MQTT'ye dogrudan baglanmaz; kapi komutu API'ye gider.
- Her ESP32 cihaz kendi MQTT kullanici/sifresiyle yalnizca kendi topic'lerine erisir.

Mimari
- Broker: Mosquitto (VPS)
- Domain: mqtt.gudeteknoloji.com.tr
- Port: 8883 (TLS)
- Auth: username/password
- Yetki: ACL (kullanici bazli topic izinleri)

Topic yapisi
- Komut: device/<UID>/cmd
- Durum: device/<UID>/state
- Olay: device/<UID>/event
- Erisilebilirlik: device/<UID>/availability
- Cevrimdisi kapi loglari: device/<UID>/logs  (cihaz -> sunucu, NDJSON toplu:
  {"batch_id":N,"logs":[...]}; sunucu device/<UID>/cmd uzerinden {"action":"logs_ack",...} ile onaylar)
- QR dogrulama istegi: device/<UID>/qr_verify  (cihaz -> sunucu, request_id ile)
- QR dogrulama sonucu: device/<UID>/qr_result  (sunucu -> cihaz, request_id aynen geri yankilanir)
- Ekran QR kodu: device/<UID>/screen_qr  (ekranli WROOM cihaz -> sunucu, retained DEGIL)
- cmd uzerinden yalniz JSON action komutlari kabul edilir (pulse, ota_check, local_control_config,
  admin_pin_config, logs_ack); duz metin "pulse"/"on" komutlari kaldirildi.

2) Paket kurulumlari (VPS)
sudo apt update
sudo apt install -y mosquitto mosquitto-clients certbot python3-certbot-nginx

3) TLS sertifikasi (Let's Encrypt)
sudo certbot certonly --nginx -d mqtt.gudeteknoloji.com.tr -m MAIL_ADRESIN --agree-tos -n

4) Sertifika dosyalarini Mosquitto yoluna bagla
sudo mkdir -p /etc/mosquitto/certs
sudo ln -sf /etc/letsencrypt/live/mqtt.gudeteknoloji.com.tr/fullchain.pem /etc/mosquitto/certs/fullchain.pem
sudo ln -sf /etc/letsencrypt/live/mqtt.gudeteknoloji.com.tr/privkey.pem /etc/mosquitto/certs/privkey.pem

sudo chown -R mosquitto:mosquitto /etc/mosquitto/certs
sudo chmod 755 /etc/mosquitto /etc/mosquitto/certs
sudo chmod 644 /etc/mosquitto/certs/fullchain.pem
sudo chmod 640 /etc/mosquitto/certs/privkey.pem

5) MQTT kullanicilarini olustur
sudo mosquitto_passwd -c /etc/mosquitto/passwd api_bridge

# Her cihaz icin:
# UID ornek: D4C771A172E0
# Kullanici ornek: device_D4C771A172E0
sudo mosquitto_passwd /etc/mosquitto/passwd device_D4C771A172E0

6) ACL dosyasini olustur
sudo tee /etc/mosquitto/acl > /dev/null <<'EOF'
user api_bridge
topic read device/+/state
topic read device/+/event
topic read device/+/availability
topic read device/+/qr_verify
topic read device/+/screen_qr
topic read device/+/logs
topic write device/+/cmd
topic write device/+/qr_result

user device_D4C771A172E0
topic read device/D4C771A172E0/cmd
topic read device/D4C771A172E0/qr_result
topic write device/D4C771A172E0/state
topic write device/D4C771A172E0/event
topic write device/D4C771A172E0/availability
topic write device/D4C771A172E0/qr_verify
topic write device/D4C771A172E0/screen_qr
topic write device/D4C771A172E0/logs
EOF

Not:
- D4C771A172E0 ornek cihaz Unique ID'sidir.
- Sunucu cihaz kaydinda mqtt_username/mqtt_password olusturur. Broker tarafinda
  ayni kullanici/sifre mosquitto_passwd ve ACL dosyasina eklenmelidir.
- Ticari urun modunda cihaz kaydi sonrasi bu islem API tarafindan otomatik
  tetiklenir. Bunun icin 6.1 adimindaki sinirli sudo komutu kurulmalidir.
- Mobil uygulamaya MQTT kullanici/sifresi verilmez. Kapi acma komutu API'ye
  gider; API, api_bridge kullanicisi ile broker'a yazar.

6.1) Otomatik broker senkronu (ticari urun modu)
- API'ye sinirsiz sudo verilmez. Sadece asagidaki tek komutu sifresiz
  calistirma yetkisi verilir.

sudo install -o root -g root -m 0755 \
  /var/www/site_kapi_kontrol/server/scripts/kapi-mqtt-sync.sh \
  /usr/local/bin/kapi-mqtt-sync

sudo tee /etc/sudoers.d/kapi-mqtt-sync > /dev/null <<'EOF'
salihceylan ALL=(root) NOPASSWD: /usr/local/bin/kapi-mqtt-sync
EOF

sudo chmod 440 /etc/sudoers.d/kapi-mqtt-sync
sudo visudo -cf /etc/sudoers.d/kapi-mqtt-sync

- server/.env icinde otomatik senkron icin:
  MQTT_SYNC_COMMAND=sudo
  MQTT_SYNC_ARGS=-n /usr/local/bin/kapi-mqtt-sync
  MQTT_SYNC_TIMEOUT_MS=30000
  MQTT_SYNC_REQUIRED=true

- Elle test:
  cd /var/www/site_kapi_kontrol/server
  sudo -n /usr/local/bin/kapi-mqtt-sync

- Bu kurulumdan sonra yeni cihaz kaydedildiginde backend DB'de cihaz MQTT
  kimligini uretir, Mosquitto ACL/passwd dosyalarini senkronlar ve Mosquitto'yu
  reload/restart eder.
- server/.env icinde su degerler tanimli olmali:
  MQTT_HOST=mqtt.gudeteknoloji.com.tr
  MQTT_PORT=8883
  MQTT_USER=api_bridge
  MQTT_PASSWORD=<api_bridge_sifresi>
  MQTT_ALLOW_INSECURE_TLS=false

7) Mosquitto secure config (tek dosya tavsiyesi)
- Eski conf dosyalarini yedekle:
  sudo mkdir -p /etc/mosquitto/conf.d.bak
  sudo mv /etc/mosquitto/conf.d/*.conf /etc/mosquitto/conf.d.bak/ 2>/dev/null || true

- Yeni dosya:
sudo tee /etc/mosquitto/conf.d/10-secure.conf > /dev/null <<'EOF'
per_listener_settings true

listener 8883
protocol mqtt

allow_anonymous false
password_file /etc/mosquitto/passwd
acl_file /etc/mosquitto/acl

certfile /etc/mosquitto/certs/fullchain.pem
keyfile /etc/mosquitto/certs/privkey.pem
tls_version tlsv1.2
EOF

8) Ana config include kontrolu
- /etc/mosquitto/mosquitto.conf icinde su satir olmali:
  include_dir /etc/mosquitto/conf.d

13) Siklikla gorulen hatalar
- "Address already in use": Elle "mosquitto -c ... -v" calistirilmis ve port dolu.
  Cozum:
  sudo systemctl stop mosquitto
  sudo pkill -9 mosquitto
  sudo systemctl start mosquitto

- "Unable to open acl_file": acl dosyasi yok/izin hatali.
  Cozum:
  sudo chown mosquitto:mosquitto /etc/mosquitto/acl
  sudo chmod 640 /etc/mosquitto/acl

- Servis surekli fail:
  sudo journalctl -xeu mosquitto.service --no-pager | tail -n 80

14) Operasyon notu
- Servis ayakta oldugunda "sudo mosquitto -c /etc/mosquitto/mosquitto.conf -v" komutunu calistirma.
- Yonetim icin systemd kullan:
  sudo systemctl restart mosquitto
  sudo systemctl status mosquitto --no-pager


15) GUVENLIK NOTLARI (yalnizca ek; yukaridaki adimlar degismedi)

a) Sudoers wrapper'i ROOT'a ait kopyadan calismali (6.1)
- /usr/local/bin/kapi-mqtt-sync dosyasi root:root, mod 0755 olmali ve API kullanicisi
  (salihceylan) tarafindan YAZILAMAMALI. Sudoers satiri yalnizca bu kopyayi gostermeli;
  repo icindeki server/scripts/kapi-mqtt-sync.sh yolu sudoers'ta ASLA kullanilmamali
  (repo dosyasini API kullanicisi degistirebilir -> root'a yukselme).
- Betik her degistiginde kopya yeniden kurulmali:
  sudo install -o root -g root -m 0755 /var/www/site_kapi_kontrol/server/scripts/kapi-mqtt-sync.sh /usr/local/bin/kapi-mqtt-sync
- Kontrol:
  ls -l /usr/local/bin/kapi-mqtt-sync        (sahip root:root, yazma yalniz root)
  sudo -l -U salihceylan                     (yalnizca kapi-mqtt-sync NOPASSWD gorunmeli)
- DIKKAT (bilinen risk): wrapper icinde `node scripts/sync_mqtt_acl.js` root olarak calisir. Bu dosya,
  import ettigi src/db.js ve node_modules API kullanicisi tarafindan yazilabilir oldugundan, API
  kullanicisinin ele gecirilmesi root'a yukselmeye donusebilir. Onerilen yon:
  (1) Node kismi yalnizca passwd/ACL TASLAGINI API kullanicisi yetkisiyle bir hazirlik dizinine
      (ornek: /var/lib/kapi-mqtt/staging, sahip salihceylan) uretsin;
  (2) root wrapper'i yalnizca taslagi dogrulasin (kullanici adi/UID regex'i), mosquitto_passwd ile
      kursun ve mosquitto'yu reload etsin;
  (3) wrapper repo yolundan HICBIR betik/modul calistirmasin.

b) Broker / ACL
- Cihaz basina ayri MQTT kullanicisi + sifre; ACL'de yalnizca kendi UID topic'leri.
- ACL satirlarina girecek UID/kullanici adi once dogrulanmali (12 haneli hex). Satir sonu veya
  bosluk iceren bir deger ACL'yi bozar / baska kullaniciya yetki ekler.
- Cevrimdisi log teslimi icin cihaz ACL'ine `topic write device/<UID>/logs`, api_bridge'e
  `topic read device/+/logs` eklenmelidir; ayrica QR sonucu icin cihaza `topic read device/<UID>/qr_result`,
  api_bridge'e `topic write device/+/qr_result`. Yukaridaki ornek ACL, API'nin urettigi ACL ile (server/src/mqtt_acl_sync.js)
  aynidir; canli ACL'i elle degil sync_mqtt_acl.js ile uretin (cihaz eklenince/silinince API tetikler).
- api_bridge sifresi hicbir betige/dosyaya yazilmaz; yalnizca server/.env (chmod 600).
  Sifre bir yere acik yazildiysa veya git gecmisine girdiyse DONDURULMALI:
  sudo mosquitto_passwd /etc/mosquitto/passwd api_bridge  ->  server/.env MQTT_PASSWORD  ->  pm2 restart kapi-api --update-env
- Broker TLS'i en az tlsv1.2; API ve cihazlarda sertifika dogrulamasi ACIK olmali
  (MQTT_ALLOW_INSECURE_TLS=false).

c) PostgreSQL portu
- docker-compose.yml artik PostgreSQL'i yalnizca 127.0.0.1:5432'e baglar. Portu disariya ACMAYIN;
  `sudo ufw status | grep 5432` bos donmeli. Uzaktan erisim gerekirse SSH tuneli:
  ssh -p 22667 -L 5432:127.0.0.1:5432 salihceylan@178.210.161.55
- Parola depo kokundeki .env dosyasindan (POSTGRES_PASSWORD) okunur; varsayilan yoktur. Mevcut
  veritabaninin parolasi veri dizininde kalir; degistirmek icin ALTER USER ... PASSWORD ... calistirip
  server/.env icindeki DB_PASSWORD'u ayni degerle guncelleyin.

d) SSH
- Parola yerine anahtar kullanin: ssh-keygen -t ed25519 ; ssh-copy-id -p 22667 salihceylan@178.210.161.55
  Anahtarla giris calistigini IKINCI bir terminalden dogruladiktan SONRA sshd_config'te
  PasswordAuthentication no ve PermitRootLogin no yapin (oturumu kapatmadan test edin).
- company_qr_tool firmware yuklerken sunucu kimligini known_hosts ile dogrular ve SSH_KEY_FILE ile
  anahtar kullanabilir; ilk kurulum adimlari company_qr_tool/README.md icindedir.
- Brute-force icin fail2ban (sshd jail, port 22667) onerilir.
